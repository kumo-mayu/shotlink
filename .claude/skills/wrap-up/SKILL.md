# 変更の仕上げ

## 1. ビルドとテスト

```powershell
dotnet build 2>&1 | Select-Object -Last 4          # 警告 0・エラー 0 を見る
dotnet test --nologo 2>&1 | Select-String '合計:|失敗 |Total|Failed'   # 件数と失敗
```

出力を丸ごと出さない（文脈を食う）。失敗したときだけ `Select-String 'error|失敗|Failed'` で該当の行を見る。
実行ファイルが掴まれて失敗したら、確かめ用に起動した ShotLink を終了する（常駐しているので、通知領域から抜けているかも見る）。
見張り・時計に絡む直しをしたときは、テストを2回走らせて揺れないことを見る。

## 2. 文書（コードだけ直して置き去りにしない）

| 変えた物 | 直す文書 |
|---|---|
| 決め事・設計・動き | `docs/spec.md`（200行を超えそうなら `docs/spec/` に話題ごとに分ける） |
| 守る決め事・作業の手順 | `CLAUDE.md` |

[決定] の項目を変える直しは、ユーザーに聞いてから。

## 3. 入れてはいけない物の点検

```powershell
git status --short
git diff --cached --stat
```

- 本物の VRChat の写真・ユーザーの写真が無いか（`git diff --cached --name-only` に `.png` `.jpg` が無いか。素材は道具で作り、画像は入れない）
- 本番の `settings.json`・`history.json`、実際に読んだ QR の中身が、試験のデータや文書に紛れていないか
- ビルドの成果物（`bin/` `obj/` `publish/`）が無いか

## 4. コミット（区切りごとに Claude が行う）

メッセージは**なぜそうしたか**を日本語で書く（`git log -5` に倣う）。1行目は何をしたかを短く、本文に理由。
末尾には、system-reminder が示す帰属の行を付ける。

**メッセージは作業用フォルダのファイルに書いてから `git commit -F <ファイル>`。**
here-string を引数に渡す書き方は Chmonos で壊れた（2026-09-14）。

```powershell
git add <ファイル>        # 変えた物を名指しで。-A は使わない
git commit -F "<作業用フォルダ>\commit-msg.txt"
```

1つのコミットに1つの理由。

## 5. プッシュはしない

`git push`・リリースの公開・BOOTH への登録はユーザーが行う（CLAUDE.md）。報告に「プッシュはまだ」と書く。

## 6. 報告（日本語）

- 何を変えたか（ユーザーの言葉で頼まれた単位で）
- 何でどう確かめたか・テストの件数
- 確かめていないこと（実際の VRChat の写真・トーストのクリック・別の PC など）
- コミットの番号
