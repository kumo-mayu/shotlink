# 測った数字

仕様書（`docs/spec.md`）の決め事の根拠にした数字。測った日と道具を添える。決め事そのものは仕様書に書き、ここには数字だけを置く。

## QR の読み取り（3.3）

2026-10-14、`tools/QrBench`（作った素材。3 解像度 × 中身 3 × 大きさ 7 × 向き 4 × ぼかし 3 = 756 枚）。

- **ZXing.Net と zxing-cpp の比べ**：左右に 45〜55° 傾いた QR（一辺が短い辺の 20%）を、ZXing.Net は 6 枚中 1 枚、zxing-cpp は 6 枚とも読めた。65° では ZXing.Net 0 枚・zxing-cpp 4 枚。1枚に3つ並べると ZXing.Net は2つ、zxing-cpp は3つ。4K の1枚で ZXing.Net 約 30 ms・zxing-cpp 約 20 ms
- **時間**（zxing-cpp）：1枚あたり 1080p 約 5 ms、4K 約 19 ms、8K 約 78 ms。QR の無い写真で読み違えたのは 0 件
- **読める範囲**（QR の一辺を写真の短い辺に対する割合で表す）
  - 読めるかどうかは大きさより、QR の1マスが何画素で写るかと、ぼけで決まる
  - ぼけが無ければ、1080p は 9%（約 100 画素）、4K は 4.5%、8K は 3% から読める
  - 1080p で 1 画素ぶんぼけると、正面で 14%、斜め 45° で 25% が要る
  - 左右に 65° 傾くと読みにくくなり、2 画素ぼけると 25% でも 3 枚に 1 枚しか読めない
- **自前の縮小・拡大**：重ねても読める数は増えなかった。2倍に拡大すると時間が 5 倍になるだけ
- 作り物なので、実際の写真での読める範囲は違いうる（仕様書 9章 [要確認]）

## メモリ（3.3）

2026-10-14、開発用の起動（`SHOTLINK_HOME`）で、作った素材を見張るフォルダへ移して測った。「ShotLink だけの分」は `PrivateMemorySize64`。

- 待ち受け 15 MB、1080p を読んだあと 19〜21 MB
- 8K を読んでいる間は一時 約 290 MB、読み終わったあと 25〜28 MB（.NET の分は 0〜4 MB で、残りは Windows の画像の部品などが持つ分）
- メモリを返す処理を入れる前は、8K のあと 51〜61 MB のまま戻らなかった
- 画像を非同期の関数の中に置くと、終わった処理が次の写真まで画像を掴み続け、8K のあと .NET の分が 36 MB 残った

## 通知（8章）

2026-10-14、作者の PC（Windows 11）で、作者がクリックして確かめた。

- `NotifyIcon` の吹き出し：出ている間のクリックは受けられた。通知センターに残らず、次を出すと前が消えた（一度に1件）
- トースト（`Microsoft.Toolkit.Uwp.Notifications`）：出ている間・通知センターに入ったあと・3件続けて出したときのどれも、どの通知をクリックしたかまで受け取れた
- 決まった AppUserModelID を付けないと、通知の登録が exe の置き場所ごとに別になった（試しの間だけで 6 件）。付けると、2つの場所から起動しても登録は1つで、クリックで起こす exe は最後に起動した場所になった
- 作者の PC は Windows の通知が全体でオフだった（`PushNotifications\ToastEnabled = 0`）。オフだと吹き出しは出てすぐ閉じ、トーストの設定は `DisabledForUser` になる

## 大きさとメモリ（8章）

2026-10-14、`win-x64`・.NET 同梱・単一ファイルで組んで測った。

| 形 | exe | zip | 起動 | 常駐のメモリ（作業セット） |
|---|---|---|---|---|
| WPF ＋ Windows Forms | 191 MB | 75 MB | 約 0.2 秒 | 約 71 MB |
| 上を圧縮（`EnableCompressionInSingleFile`） | 79 MB | 73 MB | 約 0.4 秒 | 約 229 MB |
| Windows Forms だけ（**採用**） | 137 MB | 52 MB | — | — |
| Windows Forms だけ ＋ 部分的なトリミング | 60 MB | 22 MB | — | 約 72 MB |

- いちばん大きい中身は Windows の API の橋渡し（`Microsoft.Windows.SDK.NET.dll` 22 MB）。トースト通知のために要る
- 常駐のメモリ（ShotLink だけの分）：通知領域のアイコンだけで 13 MB（.NET と Windows Forms の土台）、トースト通知を使うと 19 MB
- 部分的なトリミングは、通知の部品を丸ごと残し、COM の仕組み（`BuiltInComInteropSupport`）を残すと、通知のクリックまで動いた。残さないと、クリックを受け取る登録を作るところで落ちた
