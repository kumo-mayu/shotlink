# ShotLink 仕様書

> 作成：2026-10-14（Claude Code。経緯は idea-vault の `ideas/vrc-photo-qr-watcher.md`）
> 印：**[決定]** ユーザーが決めた／**[案]** 推奨。実装前に決めてよい／**[要確認]** 実機や資料で確かめる

## 1. 何をするソフトか

VRChat の写真フォルダを見張り、新しく撮られた写真に QR コードが写っていれば、その中身を知らせる。中身が URL ならブラウザで開く。

- 主な使い道：[Paramroom](https://github.com/kumo-mayu/Paramroom) の QR モードで相手のアバターに出た QR を、カメラで撮るだけで PC に受け取る
- Paramroom が無くても使える。ワールドのポスター・他人が見せた QR など、写真に写った QR なら何でも読む

## 2. 決まっていること

- [決定] 名前は **ShotLink**、リポジトリは `shotlink`
- [決定] **メインウィンドウを持たない常駐型**。通知領域（タスクトレイ）のアイコンだけで存在し、触れるのは設定くらい
- [決定] ブラウザで直接開くのは **`http` と `https` だけ**
- [決定] 直接開くかどうかは**設定で切り替えられる**
- [決定] Paramroom とは**別の実行ファイル・別のリポジトリ**。配り方は次の2つ
  - Paramroom の配布 zip に同梱する（Paramroom のおまけ）
  - BOOTH の単独の無料商品として出す。単独の商品にも exe 本体と説明を入れる（外部への誘導だけの商品は BOOTH で禁止されているため）

## 3. 動きの流れ

```
写真フォルダに新しいファイル
  → 書き込みが終わるのを待つ
  → 画像を読む → QR を探す（1枚に複数あれば全部）
  → 中身ごとに分ける
       http / https の URL … 「直接開く」が ON → ブラウザで開く ＋ 通知
                              「直接開く」が OFF → 通知（クリックで開く）
       それ以外（文字列・他のスキーム） … 通知（クリックでクリップボードへコピー）。開かない
  → 履歴に残す
```

### 3.1 見張る場所

- [決定事項ではないが前提] VRChat の写真の既定の場所は `%USERPROFILE%\Pictures\VRChat\` で、その下に月ごとのフォルダ（`yyyy-MM`）が作られる。ファイル名は `VRChat_yyyy-MM-dd_HH-mm-ss.fff_<幅>x<高さ>.png`（2026-10-14、作者の PC で確認）
- [案] **サブフォルダも含めて**見張る（月が変わると新しいフォルダができるため）
- [案] 写真の場所は VRChat の `config.json`（`%USERPROFILE%\AppData\LocalLow\VRChat\VRChat\config.json`）の `picture_output_folder` で変えられる。起動時にこれを読み、あればそちらを使う。月ごとに分けない設定（`picture_output_split_by_date`）もある [要確認：キー名と挙動]
- [案] 設定で見張る場所を手で指定もできる（自動で見つけた場所を上書きする）。フォルダは1つでよい
- [案] **起動前からある写真は読まない**。起動後に増えたファイルだけを対象にする
- 対象の拡張子：`.png`（VRChat の既定）。`.jpg` `.jpeg` `.webp` も読めるなら読む [案]

### 3.2 書き込み途中のファイル

- `FileSystemWatcher` の作成イベントは、VRChat がまだ書いている途中に届く。開けるまで、かつ大きさが変わらなくなるまで、短い間隔で数回試す [案：例 200ms 間隔・最大 10 秒]
- `FileSystemWatcher` は取りこぼすことがある（バッファのあふれ）。あふれたら、そのフォルダの最近のファイルを読み直す [案]

### 3.3 QR の読み取り

- [案] ライブラリは **ZXing.Net**（Apache-2.0）。1枚に複数の QR があっても読める読み取り器がある
- VRChat の写真は 1920×1080 から 4K・8K まであり、QR は写真の中で小さく・斜めに写ることが多い。大きいまま読めなければ、縮小や切り出しを変えて何度か試す [案]。どこまで試すかは速さとの兼ね合いで、実機の写真で決める [要確認]
- 読み取りは裏のスレッドで行い、1枚ずつ順に処理する

### 3.4 同じ QR が何度も来たとき

- 同じ相手を続けて撮ると、同じ QR が何枚にも写る。**同じ中身は一定時間（[案] 60 秒）2回目以降を開かない・知らせない**
- 1枚の写真に同じ中身の QR が複数あっても1回だけ扱う

## 4. 安全のための決まり

写真に写った QR は**他人が用意したもの**であることが多い。VRChat の中で見せられた QR を撮っただけで、知らない URL が開くことがある。

- [決定] 直接開くのは `http` と `https` だけ。`file:` `javascript:` `ms-settings:` などの他のスキームや、スキームの無い文字列は**絶対に開かない**（クリップボードへのコピーだけ）
- [案] 「直接開く」の**既定は OFF**。初めて使う人は、通知を見てからクリックで開く。ON にする場所で危険を一言書く
- [案] 通知には URL の**ホスト名をはっきり見せる**。国際化ドメイン（`xn--`）はそのまま表示し、見た目の似た偽のドメインに気づけるようにする
- [案] 直接開く場合も、**短い時間に開く回数に上限**を設ける（例：1分に3件まで。超えた分は通知だけ）
- URL を開くときは、既定のブラウザに渡すだけにする（`UseShellExecute`）。引数を組み立ててコマンドに混ぜない
- [案] このソフト自身は**ネットに一切つながない**（更新の確認もしない）。写真も QR の中身もどこへも送らない。README と BOOTH のページにもそう書く

## 5. 通知領域のアイコンとメニュー

アイコンを右クリックしたときのメニュー [案]：

| 項目 | 動き |
|---|---|
| 最近読んだ QR（直近 [案] 10件） | 項目を選ぶと、URL なら開く・それ以外はコピー |
| 見張りを一時停止 ／ 再開 | 止めている間はアイコンの見た目を変える |
| URL を直接開く（チェック） | 3章の「直接開く」の ON/OFF。よく切り替えるのでメニューに直接置く |
| 設定… | 小さな設定の窓を開く |
| 写真フォルダを開く | エクスプローラーで開く |
| 終了 | |

- アイコンをダブルクリック：[案] 設定の窓を開く
- 通知（Windows のトースト）をクリック：URL なら開く、それ以外はコピー

## 6. 設定

小さな窓1枚。項目 [案]：

- URL を直接開く（既定 OFF）
- URL 以外の QR も知らせる（既定 ON）
- 見張る場所：自動（VRChat の設定から）／手で指定
- Windows の起動時に自動で起動する（既定 OFF。`HKCU\...\Run` に登録）
- 通知の音を鳴らす
- このアプリについて：版・ライセンス・第三者のライセンス・「VRChat Inc. とは関係のない非公式のツール」である旨

保存先：`%LOCALAPPDATA%\ShotLink\`（`settings.json`、`history.json`、`Logs\`）。実行ファイルの隣には書かない（Chmonos・PresetRecorder と同じ考え方）。

## 7. そのほかの動き

- **1つしか起動しない**（2つ目を起動したら、1つ目の設定の窓を開いて終わる）
- 写真フォルダが見つからない・消えたときは、アイコンの見た目と通知で知らせ、フォルダができたら自動で見張りを再開する
- 写真は**読むだけ**で、動かしたり書き換えたりしない
- ログは日ごとのファイルにし、古いものは消す（[案] 7日）。QR の中身は履歴に残すが、ログにはホスト名までにする [案]

## 8. 技術

- [案] C# / WPF / **.NET 10**（`net10.0-windows`。Chmonos と同じ。SDK は `global.json` で固定）
- [案] 通知領域のアイコン：WPF に部品が無いので、Windows Forms の `NotifyIcon`（`UseWindowsForms`）か H.NotifyIcon を使う
- [案] トースト通知：通知をクリックしたときの動作が要る。方法（CommunityToolkit の通知部品か、Windows App SDK か）は、配布形態（下）と合わせて最初に試して決める [要確認]
- 配布：`win-x64` の self-contained・単一ファイル（Paramroom の `make-release.sh` と同じ形）。インストーラーは無し
- [案] ライセンスは MIT（Paramroom と同じ）。ZXing.Net など同梱するライブラリは `THIRD-PARTY-NOTICES.txt` に書く

## 9. テスト

- QR の読み取りと中身の振り分け（スキームの判定、同じ中身の重複の除外、開く回数の上限）は、UI と切り離してテストできる形にする
- 実際の VRChat の写真（QR あり・なし・複数・小さい・斜め、4K・8K）を数枚 `tests` の素材に置く
- 見張りの確認は、素材の画像を見張っているフォルダへ**移動**すればよい（毎回撮らなくてよい）。書き込み途中の再現には、少しずつ書き込む小さな道具を使う

## 10. やらないこと

- メインウィンドウ、写真の閲覧・整理
- 写真や QR の中身をどこかへ送ること
- 起動前に撮られた写真の読み取り
- VRChat 以外のスクリーンショットのための機能（見張る場所を手で指定すれば読めるが、そのための機能は足さない）

## 11. 配布の段取り

- GitHub の Releases に zip（exe・README・LICENSE・THIRD-PARTY-NOTICES.txt）
- BOOTH：単独の無料商品として同じ zip を置く
- Paramroom：Paramroom の `make-release.sh` が ShotLink の最新の Releases から exe を取ってきて、Paramroom の zip に入れる。Paramroom の版を出すときに、その時点の最新を入れ直す（ShotLink を更新するたびに Paramroom を差し替えはしない）。同梱の README に「最新版は ShotLink の商品ページへ」と書く
- 名前：公開前に J-PlatPat で「ShotLink」を引く [要確認]。VRChat の名前の使い方（「for VRChat」などの書き方）も、VRChat の商標のガイドラインで確かめる [要確認]

## 12. 決めていないこと

- 「直接開く」の既定を OFF にするか（上は OFF を推奨）
- 同じ中身を無視する時間・開く回数の上限の値
- トースト通知の実装方法
- QR を探すときの試し方（縮小・切り出し）の範囲
