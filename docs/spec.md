# ShotLink 仕様書

> 作成：2026-10-14（Claude Code。経緯は idea-vault の `ideas/vrc-photo-qr-watcher.md`）
> 印：**[決定]** ユーザーが決めた／**[案]** 推奨。実装前に決めてよい／**[要確認]** 実機や資料で確かめる
> 決め事の根拠の数字は `docs/spec/measurements.md`、名前とライセンスの調べは `docs/spec/names-and-licenses.md`、設定の窓の項目は `docs/spec/settings.md`。このファイルは 200 行までにする

## 1. 何をするソフトか

VRChat の写真フォルダを見張り、新しく撮られた写真に QR コードが写っていれば、その中身を知らせる。中身が URL ならブラウザで開く。

- 主な使い道：[Paramroom](https://github.com/kumo-mayu/Paramroom) の QR モードで相手のアバターに出た QR を、カメラで撮るだけで PC に受け取る
- Paramroom が無くても使える。ワールドのポスター・他人が見せた QR など、写真に写った QR なら何でも読む

## 2. 決まっていること

- [決定] 名前は **ShotLink**、リポジトリは `shotlink`
- [決定] **メインウィンドウを持たない常駐型**。通知領域（タスクトレイ）のアイコンだけで存在し、触れるのは設定くらい
- [決定] ブラウザで直接開くのは **`http` と `https` だけ**
- [決定] 直接開くかどうかは**設定で切り替えられる**
- [決定] Paramroom とは**別の実行ファイル・別のリポジトリ**。配り方は次の2つ
  - Paramroom の配布 zip に同梱する（Paramroom のおまけ）
  - BOOTH の単独の無料商品として出す。単独の商品にも exe 本体と説明を入れる（外部への誘導だけの商品は BOOTH で禁止されているため）

## 3. 動きの流れ

```
写真フォルダに新しいファイル
  → 書き込みが終わるのを待つ
  → 画像を読む → QR を探す（1枚に複数あれば全部）
  → 中身ごとに分ける
       http / https の URL … 「直接開く」が ON → ブラウザで開く ＋ 通知
                              「直接開く」が OFF → 通知（クリックで開く）
       それ以外（文字列・他のスキーム） … 通知（クリックでクリップボードへコピー）。開かない
  → 履歴に残す
```

### 3.1 見張る場所

- [決定事項ではないが前提] VRChat の写真の既定の場所は `%USERPROFILE%\Pictures\VRChat\` で、その下に月ごとのフォルダ（`yyyy-MM`）が作られる。ファイル名は `VRChat_yyyy-MM-dd_HH-mm-ss.fff_<幅>x<高さ>.png`（2026-10-14、作者の PC で確認）
- [決定] 見張る場所は次の2つを**同時に**使える
  - **VRChat の写真フォルダ**（自動で見つける）。ON/OFF できる
  - **追加のフォルダ**（手で指定する）。**複数**指定できる。VRChat 以外のスクリーンショット（Steam・ShareX など）のフォルダを想定
- VRChat の写真フォルダ
  - [決定] **サブフォルダも含めて**見張る（月が変わると新しいフォルダができるため）
  - [案] 写真の場所は VRChat の `config.json`（`%USERPROFILE%\AppData\LocalLow\VRChat\VRChat\config.json`）の `picture_output_folder` で変えられる。起動時にこれを読み、あればそちらを使う。月ごとに分けない設定（`picture_output_split_by_date`）もある [要確認：キー名と挙動]
- 追加のフォルダ
  - [決定] サブフォルダも含めるかどうかを**フォルダごとに**選べる（既定 OFF。`Pictures` 全体などを指定されたときに重くならないように）
- [決定] ネットワーク上のフォルダ（`\\server\share` など）も、利用者が指定したなら受け付ける。設定の窓に「ネットワーク上のフォルダを選ぶと、ShotLink はそこへアクセスします」と書く（2026-10-14 ユーザー判断。ShotLink から何かを送るわけではない）
- 同じフォルダが重なったとき（追加のフォルダが VRChat のフォルダの中にある、など）は、1つのファイルを1回だけ扱う [決定]
- [決定] **起動前からある写真は読まない**。起動後に増えたファイルだけを対象にする
- [決定] **一時停止の間に増えた写真も、再開したあとに読まない**（起動前の写真と同じ扱い。止めた理由が「読まれたくない」だったときに、あとからまとめて開かないように）
- 対象の拡張子：`.png` `.jpg` `.jpeg` `.webp`（VRChat の既定は `.png`。他のスクショ道具は `.jpg` が多い）[決定]

### 3.2 書き込み途中のファイル

- `FileSystemWatcher` の作成イベントは、VRChat がまだ書いている途中に届く。[決定] 200 ms おきに見て、開けて大きさが2回続けて同じで、**形式の終わりの印がそろったら**読む（PNG は最後が IEND、WebP は頭に書かれた全体の大きさ、JPEG は最後が FFD9。JPEG の印が無いときと知らない形式は、大きさが 1 秒変わらなければ読む）。10 秒で書き終わらなければあきらめる
  - [決定] 書き終わったら、ファイルを丸ごと写し取り、写しが1つの画像として揃っているか（PNG は全部の塊の CRC と IEND で終わるか）を確かめてから、写しを読む。VRChat が保存したあとに 写真に情報を書き足す道具が同じファイルを書き直して情報を足すので、ファイルから直に読むと、8K の読み込み（約 0.5 秒）の間に中身が混ざる（作者の実機で 8K 9 枚中 8 枚を取りこぼした）。揃っていなければ 0.2 秒後に写し直す
  - 途中の PNG は、Windows の画像の部品がエラーを出さずに読み、下の方が黒い画像になる。最初は大きさだけで見ていて、VRChat が 8K を書く合間に手を止めた所で読み、作者の実機で 8K の写真 4 枚とも QR を取りこぼした（2026-10-14。`docs/spec/measurements.md`）
- `FileSystemWatcher` は取りこぼすことがある（バッファのあふれ）。あふれたら、そのフォルダの最近のファイルを読み直す [決定]。見張りはフォルダごとに持つので、読み直しもフォルダごと

### 3.3 QR の読み取り

- ライブラリは **zxing-cpp**（Apache-2.0。.NET 向けの包み ZXingCpp。ネイティブの DLL が約 3 MB 増える）。作った素材で ZXing.Net と比べて決めた（2026-10-14）
  - 斜めの QR と1枚に複数の QR で、zxing-cpp の方がはっきり多く読めた（数字は `docs/spec/measurements.md`）
- VRChat の写真は 1920×1080 から 4K・8K まであり、QR は写真の中で小さく・斜めに写ることが多い
- 縮小・切り出し・拡大を自前で重ねることはしない。zxing-cpp の中の試し（`TryHarder`・`TryRotate`・`TryDownscale`）だけで、重ねても読める数は増えなかった
- 1枚あたり 8K でも 0.1 秒かからない。読めるかどうかは大きさより、**QR の1マスが何画素で写るか**と**ぼけ**で決まる（読める範囲は `docs/spec/measurements.md`）。作り物の素材で測ったので、実際の写真では違いうる [要確認]（9章）
- 読み取りは裏のスレッドで行い、1枚ずつ順に処理する
- [決定] 1枚を処理し終えたら、画像に使ったメモリを Windows に返す。返さないと、8K を1枚読んだあと待ち受けのメモリが増えたまま戻らない
  - 画像を非同期の関数の中に置くと、終わった処理が次の写真まで画像を掴み続ける。読み込みと読み取りは非同期でない関数に分ける

### 3.4 同じ QR が何度も来たとき

- [決定] 撮った QR は**毎回知らせる**（2026-10-14 ユーザー判断）。同じ中身の通知は前の通知を置き換え、通知センターに同じ物が並ばないようにする。最初は「最後に見てから 60 秒は知らせない」だったが、撮るたびに延びて、同じ物を撮り続けると黙ったままになり、撮ったのに出たり出なかったりした（作者の実機）
- [決定] 同じ URL をブラウザで直接開くのは、**最後に開いてから 60 秒に1回**（開かなかった通知には「少し前に開いたので開きませんでした」と書き、クリックで開ける）。「同じ URL」はブラウザに渡す形（`Uri.AbsoluteUri`。ホストの大文字・既定のポート・末尾の `/` をそろえた形）で比べる（2026-10-18。原文で比べると表記違いで抜けられた）。秒数は設定で 1〜3600 秒に変えられ、「同じ URL は連続して開かない」を外すと毎回開く（2026-10-17 ユーザー判断）。同じ相手を続けて撮って、同じタブが何枚も開かないように
- 1枚の写真に同じ中身の QR が複数あっても1回だけ扱う

### 3.5 1枚に QR が複数あるとき（2026-10-14 ユーザー判断）

- [決定] 通知・履歴・開く順は、**写真の中の位置**（左上から右下へ。上下に重ならないものは上から、同じ高さなら左から）にそろえる
- [決定] 1枚から **4件以上**（設定で 2〜99 件。1枚の中の同じ中身を除いた数。少し前に見た中身も数える）読めたら、通知を **1件にまとめる**（「QR を 10 件読みました」）。ポスターが並んだワールドなどで、通知が何十件も並ばないように
  - まとめた通知をクリックすると、**その写真で読んだ QR の一覧の小さな窓**を開き、そこで1件ずつ開く・コピーを選ぶ（メニューは ShotLink からは開けない）
  - まとめたときは、「直接開く」が ON でも**既定では開かない**。どれが目当ての QR か ShotLink には分からず、上から3件を開いても当たるとは限らない。設定の「まとめた通知の URL もすべて開く」を ON にすると、位置の順に全部開く
  - 履歴にはまとめずに1件ずつ残す
  - [決定] 設定でまとめないこともできる。そのときは何件あっても1件ずつ知らせ、「直接開く」が ON なら全部開く（2026-10-17 ユーザー判断）

### 3.6 ホワイトリスト（2026-10-17 ユーザー判断）

- [決定] 「ホワイトリストに絞る」を ON にすると、直接開くのは一覧のサイトだけ。一覧に無い URL は開かず、通知に「ホワイトリストに無いので開きませんでした」と書き、クリックで開ける
- [決定] ホスト名で比べ、**下位のドメインも含める**（`example.com` で `www.example.com` も開く。`example.com.evil.example` は開かない）。国際化ドメインは `xn--` の形にそろえて比べる。URL を貼ったらホスト名だけを使う

## 4. 安全のための決まり

写真に写った QR は**他人が用意したもの**であることが多い。VRChat の中で見せられた QR を撮っただけで、知らない URL が開くことがある。

- [決定] 直接開くのは `http` と `https` だけ。`file:` `javascript:` `ms-settings:` などの他のスキームや、スキームの無い文字列は**絶対に開かない**（クリップボードへのコピーだけ）
- [決定] 「直接開く」の**既定は OFF**。初めて使う人は、通知を見てからクリックで開く。ON にする場所で危険を一言書く
- [決定] 「直接開く」は**見張っている全部のフォルダ**に同じように効く（追加のフォルダだけ通知のみ、のような分け方はしない）
- [決定] 追加のフォルダを選ぶ画面で、「ダウンロードなど、他人の画像が入るフォルダを選ぶと、その画像の QR も読む（直接開くが ON なら開く）」と一言書く
- [決定] 通知には URL の**ホスト名をはっきり見せる**。国際化ドメイン（`xn--`）はそのまま表示し、見た目の似た偽のドメインに気づけるようにする
- 通知・メニュー・一覧に見せる文字列からは、向きを変える文字（U+202E など）と幅の無い文字を取り除く（2026-10-18。残すと見える文字の順を偽れた）。開く URL とコピーする原文はそのまま
- [決定] 直接開く回数の**上限は設けない**（2026-10-14 ユーザー判断。最初は 1分に3件だった）。写真は利用者が1枚ずつ撮る物で、1枚に多数ある場合は 3.5 のとおりまとめて既定では開かないので、上限は続けて撮る人の邪魔になるだけだった
- URL を開くときは、既定のブラウザに渡すだけにする（`UseShellExecute`）。引数を組み立ててコマンドに混ぜない
- [決定] このソフト自身は**ネットに一切つながない**（更新の確認もしない。仕様がそう何度も変わるものではないため）。写真も QR の中身もどこへも送らない。README と BOOTH のページにもそう書く

## 5. 通知領域のアイコンとメニュー

アイコンを右クリックしたときのメニュー [決定]：

| 項目 | 動き |
|---|---|
| 最近読んだ QR（直近 [決定] 10件） | 項目を選ぶと、URL なら開く・それ以外はコピー。最後の「すべて表示…」で、履歴 100 件の一覧の窓を開く（3.5 のまとめた通知と同じ窓） |
| 監視を一時停止 ／ 再開 | 止めている間はアイコンの見た目を変える |
| URL を直接開く（チェック） | 3章の「直接開く」の ON/OFF。よく切り替えるのでメニューに直接置く |
| 設定… | 小さな設定の窓を開く |
| 写真フォルダを開く | エクスプローラーで開く。見張るフォルダが複数あるときはサブメニューで選ぶ |
| 終了 | |

- アイコンをダブルクリック：[決定] 設定の窓を開く
- 通知（Windows のトースト）をクリック：URL なら開く、それ以外はコピー

## 6. 設定

小さな窓1枚。項目と文言は `docs/spec/settings.md`（2026-10-17 ユーザーが決めた並び）。見出しで組ごとに畳める。

保存先：`%LOCALAPPDATA%\ShotLink\`（`settings.json`、`history.json`、`Logs\`）。実行ファイルの隣には書かない（Chmonos・PresetRecorder と同じ考え方）。

[決定] 環境変数 `SHOTLINK_HOME` で保存先を差し替えられる（Chmonos の `CHMONOS_HOME` と同じ）。試験と確かめの起動は必ずこれを付け、本番の設定と履歴に触れない。

## 7. そのほかの動き

- **1つしか起動しない**（2つ目を起動したら、1つ目の設定の窓を開いて終わる）
- 見張るフォルダが見つからない・消えたときは、アイコンの見た目と通知で知らせ、フォルダができたら自動で見張りを再開する（フォルダごとに。1つが消えても他は見張り続ける）
- 写真は**読むだけ**で、動かしたり書き換えたりしない
- ログは日ごとのファイルにし、古いものは消す（[決定] 7日）。QR の中身は履歴に残すが、ログにはホスト名までにする [決定]

## 8. 技術

- C# / **Windows Forms** / **.NET 10**（SDK は `global.json` で固定）。[決定] WPF は使わない（2026-10-14、ユーザー判断）。窓は設定の1枚だけで Windows Forms で足り、WPF を外すと exe が 191 MB から 137 MB になる
- 通知領域のアイコン：Windows Forms の `NotifyIcon`（`UseWindowsForms`）。部品を足さずに済む
- 通知：**トースト**（`Microsoft.Toolkit.Uwp.Notifications` 7.1.3。MIT）。TFM は `net10.0-windows10.0.17763.0`。2026-10-14 に実機で試して決めた
  - `NotifyIcon` の吹き出しは、Windows 11 では**通知センターに残らず**、**一度に1件**しか出せない。トーストは、通知センターからも、続けて出した通知からも、どれをクリックしたかまで受け取れた（`docs/spec/measurements.md`）
  - この部品は、クリックを受け取るために Windows へ ShotLink を登録する（`HKCU\Software\Classes\AppUserModelId\…` と COM の登録、`%LOCALAPPDATA%\ToastNotificationManagerCompat\` のアイコン）。インストーラーが無いので、exe を消しても残り、`設定 → システム → 通知` の一覧にも残る
  - [決定] 起動の最初に**決まった AppUserModelID**（`KumoMayu.ShotLink`）を付ける。付けないと登録が exe の置き場所ごとに別になり、版を上げて別のフォルダに展開するたびに通知の一覧に「ShotLink」が増える。付けると、別の場所から起動しても登録は1つにまとまる
  - [決定] 設定の窓に「通知の登録を消して終了する」を置き（部品の `Uninstall`）、README に「消す前に押す」と書く
  - [決定] **Windows の通知がオフの人**には通知が見えない（作者の PC が実際にそうだった）。起動時と設定の窓で調べ、オフならアイコンとツールチップで「メニューの『最近読んだ QR』から開ける」と知らせる。「直接開く」が ON なら、通知が出なくても開く
- [決定] 配布：`win-x64` の self-contained・単一ファイル（Paramroom の `make-release.sh` と同じ形）。インストーラーは無し。使う人に .NET を入れてもらう手順を増やさないため
  - 大きさは exe 137 MB・zip 52 MB（形ごとの比べは `docs/spec/measurements.md`）
  - [決定] トリミング（`PublishTrimmed`）は**使わない**（ユーザー判断）。exe は 60 MB まで縮むが、Windows Forms のトリミングは Microsoft が公式に対応していない
  - [決定] 単一ファイルの圧縮（`EnableCompressionInSingleFile`）は**使わない**。zip はほぼ同じ大きさのまま、常駐のメモリが 3 倍になる
- 画像は Windows の部品（WIC。`Windows.Graphics.Imaging` から使う）で読む。ライブラリを足さずに PNG・JPEG・WebP が読める。WebP は Windows 11 なら最初から読め、Windows 10 では「WebP 画像拡張機能」が要る [要確認：WebP は実物で読んでいない]
  - 灰色（Gray8）で受け取れれば 8K でも 33 MB で済む。受け取れない形式だけ BGRA でもらって直す
- 配る形は `ShotLink.App/Properties/PublishProfiles/win-x64.pubxml`（`dotnet publish ShotLink.App -p:PublishProfile=win-x64` で `publish\ShotLink-win-x64\ShotLink.exe` 1つ）
- [決定] 対応する Windows は **Windows 10（1809 以降）と 11 の 64 ビット版**だけ。ARM 版の Windows は対応しない。画面の言葉は**日本語だけ**
- [決定] ライセンスは MIT（Paramroom と同じ）。zxing-cpp（と、その中の libzint。BSD-3-Clause）など同梱するライブラリは `THIRD-PARTY-NOTICES.txt` に書く

## 9. テスト

- QR の読み取りと中身の振り分け（スキームの判定、同じ URL を開く間隔、まとめる件数）は、UI と切り離してテストできる形にする
- [決定] 読み取りの素材は **Claude が作る**（2026-10-14、ユーザ判断）。ZXing の書き出し器で QR を描き、1920×1080・4K・8K の背景に、縮小・斜め・ぼかし・複数・QR なしの組み合わせで貼る
  - リポジトリに入れるのは**素材を作る道具**だけにし、作った画像は入れない（8K の PNG は1枚で数十 MB になる）。試験は画素の並びを作ってそのまま読ませる（`ShotLink.Fixtures`）
  - 読める範囲と時間は `dotnet run -c Release --project tools/QrBench` で測る（約 2 分）。見本の PNG は `-- --dump <フォルダ>`
  - 作り物は、実際の描画（アンチエイリアス・アバターのテクスチャの縮小・光の当たり方）とは違う。QR を探す試し方の範囲はこの素材で決めるが、実際の写真で読めるかは別に確かめる [要確認：ユーザが実際の写真を数枚、リポジトリの外に置いて試す]
- 見張りの確認は、素材の画像を見張っているフォルダへ**移動**すればよい（毎回撮らなくてよい）。書き込み途中の再現には、少しずつ書き込む小さな道具を使う

## 10. やらないこと

- メインウィンドウ、写真の閲覧・整理
- 写真や QR の中身をどこかへ送ること

## 11. 配布の段取り

- [決定] 最初に出す版は **1.0.0**。リポジトリは **`kumo-mayu/shotlink`**（Paramroom の `make-release.sh` がここの最新版を取りに行く）
- [決定] 配る zip は Chmonos と同じく、**タグを push すると GitHub Actions が組んで Releases に下書きとして置く**。公開はユーザーが押す
- [決定] 最初は**コード署名なし**。初回に Windows の「発行元不明」の警告が出ることを README に書く
- GitHub の Releases に zip（exe・README・LICENSE・THIRD-PARTY-NOTICES.txt）
  - zip の README は `docs/booth/zip-README.txt`（`{version}` を埋める。【未定】が残っていると tag の組み立ては止まる）
  - `THIRD-PARTY-NOTICES.txt` は exe に入る部品すべて（.NET の実行環境・Windows Forms・通知の部品・C#/WinRT・Windows SDK の定義・zxing-cpp・libzint）の許諾文。SDK や部品の版を上げたら `node tools/release/make-notices.mjs` で組み直す。組み立ては、告知の版と同梱する版が合わなければ止まる
  - 版を出す手順：`Directory.Build.props` の `Version` を上げてコミット → tag `v<版>` を push（ユーザー）→ 下書きの中身を確かめて公開（ユーザー）
  - [決定] `Microsoft.Windows.SDK.NET.dll`・`WinRT.Runtime.dll` は Windows SDK のライセンス条項で配られ、再配布してよい一覧に載っている。zip の README と THIRD-PARTY-NOTICES.txt に「これらは Microsoft の条項に従い、MIT は及ばない」と書く（2026-10-14 ユーザー判断。調べは `docs/spec/names-and-licenses.md`）
- BOOTH：単独の無料商品として同じ zip を置く
- Paramroom：Paramroom の `make-release.sh` が ShotLink の最新の Releases から exe を取ってきて、Paramroom の zip に入れる。Paramroom の版を出すときに、その時点の最新を入れ直す（ShotLink を更新するたびに Paramroom を差し替えはしない）。同梱の README に「最新版は ShotLink の商品ページへ」と書く
  - 作った（2026-10-14、Paramroom の a516fec）：`make-release.sh` の4つ目の引数で版を選ぶ（既定 latest、none で入れない）。`tools/release/fetch-shotlink.sh` が ShotLink の zip を取り、`.sha256` で確かめ、フォルダ（exe・README・LICENSE・THIRD-PARTY-NOTICES.txt）ごと Paramroom の zip に入れる。ShotLink の公開前は none を付ける
- 名前とライセンスの調べ（2026-10-14、Claude。判断はユーザー）：`docs/spec/names-and-licenses.md`。日本の商標に同じ読みの物は無く、近い読みの物（ShortLinks・SHOWLINK など）がある。「VRChat」は提供・承認を装わなければ用途を示すために使ってよい
